# 答题页面保存失败排查（2026-09-04）

## 实测结果

在公网入口 `https://3291s7j730.picp.vip` 排查练习 68：

- 页面已显示“无法连接服务器，请检查网络或稍后重试 / 保存失败，请重试”；重试“下一题”后仍停留在第一题并再次失败。
- `GET /api/health` 返回 200，单次测量约 0.916 秒。
- 不带登录凭据，以空 JSON 请求 `PATCH /api/exercises/sessions/68/position`，两次均出现 curl 52 `Empty reply from server`，没有 HTTP 状态码。
- 同一路径改用 `POST`，返回 Uvicorn 的 405，`Allow: PATCH`，说明请求能正常到达应用，而线上旧版本尚未支持 POST 保存位置。
- 不带登录凭据请求 `POST /api/exercises/sessions/68/answers/0` 返回应用的 401“请先登录”。这些探测没有修改线上答案或进度。

证据指向公网链路中的穿透服务或中间代理对 PATCH 方法的处理异常。尚未取得内网直连结果或服务器/穿透客户端日志，因此不能进一步断言是哪一跳或哪个产品配置导致断开，也不能排除其他时段的网络故障。

## 为什么点选答案后切题、退出会失败

`ExercisePage` 点选答案时通过 POST 保存答案；切题和保存退出会另外请求 `/position` 保存当前题号，旧版本采用 PATCH，位置请求失败会阻止切题或退出。

`api.ts` 在 fetch 抛出连接错误时统一显示“无法连接服务器”，因此这一提示不代表答案一定未保存，也不代表服务器整体不可用。普通 HTTP 401、403、405、500 响应会走另一条错误处理路径。

## 本次修复

- 位置保存改为 POST；后端同时保留 PATCH 别名，鉴权、来源检查和所属用户校验不变。
- 客观题保存也纳入待保存队列；切题、退出和提交前等待完成。失败答案保留在当前页面内存中，再次切题或退出时重试；关闭/刷新页面前有未保存提醒。此队列不是持久化离线存储。
- 同一题的答案按顺序发送，避免快速改选时旧答案后写入；位置响应只合并位置，不用旧快照覆盖刚编辑的答案。
- 成功恢复保存后清除旧错误提示。

前后端必须一起更新，或先更新后端再更新前端。只更新前端会在旧后端得到 405。后续成绩重试修复新增了 `0013_attempt_request_id` 数据库迁移，见文末。

待页面已有答案保存成功后重新加载新前端，确认开发者工具 Network 中 `/position` 使用 POST，返回 200；依次验证选答案、下一题、上一题、保存退出、重新进入后的答案和题号。

如果仍失败，保存失败请求的时间、方法、路径、HTTP 状态或浏览器 `net::ERR_*`，与服务器及穿透客户端同一时刻日志比对。避免共享 Cookie、令牌或含答案内容的完整 HAR。

以下为不带登录凭据的只读诊断探测（请求应被鉴权拒绝，不写入数据）。分别把 BASE 设置为公网入口和内网服务器入口进行对比：

```bash
BASE=https://3291s7j730.picp.vip
curl -i --max-time 15 "$BASE/api/health"
curl -i --max-time 15 -X PATCH -H 'Content-Type: application/json' --data '{}' "$BASE/api/exercises/sessions/68/position"
curl -i --max-time 15 -X POST -H 'Content-Type: application/json' --data '{}' "$BASE/api/exercises/sessions/68/position"
```

新版本的 POST、PATCH 都应由应用返回 401。如果内网 PATCH 为 401、公网 PATCH 仍为空响应，可进一步确认故障位于穿透/代理链路；结合该链路的 HTTP 方法限制及访问/错误日志定位，不需要关闭鉴权或放宽来源校验。

## 网络异常恢复修复

1. **打字与单词成绩**：失败后保留本次提交内容和唯一请求标识；15 秒超时后可以点击“重试保存成绩”。重试保留原始耗时、错误次数和测速字符数。保存中禁止重练；失败后可重试，或经确认放弃本次成绩再重练。返回按钮及刷新/关闭页面有未保存提醒；离开后不再执行迟到响应引发的切题计时器。待提交内容仅保留于当前页面内存，并非跨刷新离线存储。
2. **成绩接口去重**：新增可选 `request_id`，以学生 ID 和请求标识的唯一索引防止并发重试产生重复成绩；同一标识携带不同内容返回 409。数据库提交成功但响应丢失时，重试返回原成绩。不同学生互不影响；没有标识的旧客户端保留原行为。
3. **后台保存与刷新**：学生/课程、单词、题套的 action 分开处理写入和刷新；确认写入成功后返回成功状态，刷新失败显示“操作已完成，但列表刷新失败”，提供只重新读取数据的“重试刷新”。排序成功不会因为刷新失败而回退。PDF 上传、识别任务创建、题目图片保存及迁移包导入也使用这个处理方式。题目草稿保存成功而复核失败时，明确区分两个阶段。
4. **创建表单**：添加学生、创建课程只在确认保存成功后清空；失败保留输入。提交期间禁用输入及提交按钮，并防止连续点击重复发送。
5. **退出登录**：捕获连接失败与 15 秒超时，在页面内显示“未能确认退出登录”并提供重试；请求未完成时禁止重复点击。

### 部署注意事项

本次新增迁移 `0013_attempt_request_id`：向 `practice_attempts` 增加两个可空字段及唯一索引，不改写历史成绩。迁移测试覆盖已有成绩及错误明细保留，以及唯一索引的约束。

部署前备份数据库，重建 Web 服务时入口脚本会自动运行 `alembic upgrade head`。必须先部署支持请求去重的后端和迁移，再使用新前端的成绩重试功能；不要仅替换前端静态文件。

验收时可在测试账号完成一条打字/单词练习前断网，确认失败提示和重试按钮；恢复网络后重试，确认只有一条成绩、耗时不包含等待重试的时间。再验证后台创建失败保留输入、写入成功但刷新失败只重试读取、退出登录失败仍可再次尝试。

## 第二轮恢复修复（2026-09-04）

- 重置学习数据确认成功后立即关闭确认弹窗；报告读取失败时只提供重新读取，避免误重复执行删除。
- 整套交卷从准备保存开始暂停编辑；提交响应丢失或后续读取失败时保留锁定状态，通过“重新确认提交结果”读取服务端状态，不自动重发交卷。确认仍未提交后恢复编辑，确认已提交后显示判题或结果。
- 全站采用支持路由阻止的数据路由。未保存答案、待重试成绩和未确认的交卷在顶部首页、浏览器返回、内部返回、刷新/关闭及退出登录时均受保护；退出登录失败会恢复离开提醒。
- 普通请求默认 15 秒，FormData 上传和文件下载默认 120 秒，可按请求覆盖。截止时间包含响应体读取，调用方取消仍保留 AbortError。写入不自动重试，超时不能证明服务器未执行。
- JSON API 拒绝 HTML 成功页和截断 JSON，避免误清除待保存数据；下载拒绝 HTML 错误页。
- 运行样例的 60 次轮询用尽或读取失败后保留任务 ID，允许继续查询同一个任务；离开页面停止后续轮询。
- 登录状态读取仅在 401 时转到登录；连接失败保留原 URL，可重试连接。
